crew + Wrangler
Quick start How it works Views GitHub

A documentation-driven agent team for your Obsidian vault

crew is a standalone Bun CLI and server: the manager and central comms for a team of AI agents. Wrangler is the Obsidian plugin that starts it, and shows the team as views inside your vault. Tasks, verdicts, and traces are the documentation -- written as the work happens, so it can't drift from what was built.

Quick start

Wrangler isn't in the Obsidian community plugin directory yet, so install it with one command:

curl -fsSL https://raw.githubusercontent.com/roninito/crew/main/scripts/install-wrangler.sh | bash -s -- "/path/to/your/vault"

Then open Obsidian, go to Settings → Community plugins, and enable Wrangler. That's the whole install -- no Bun, no source checkout. The first time it's enabled in a vault, Wrangler:

  • creates the crew/ folder layout, templates, wiki, and skill
  • generates the API token in crew/crew.md
  • downloads the right crew binary for your OS from GitHub Releases
  • starts the server

Prefer to have a copilot do this for you? Point it at the wrangler-setup skill and ask it to set up crew in your vault.

How the pieces talk

crew does all the work, so the team keeps running even when Obsidian is closed. Wrangler gives it a face inside Obsidian.

PieceWhat it isResponsibilities
crewBun CLI + long-running serverState broker, event bus, scheduler, agent launcher, job runner, locks, budgets, verification, traces
WranglerObsidian pluginSets up crew/ on first enable, starts or attaches to crew serve, renders views, sends UI actions to crew
crew-manager skillA skill folder in the vaultTeaches your copilot how to run the team through crew

Everything is files in crew/ inside the vault. crew is the only writer of shared state -- agents, Wrangler, your copilot, and other tools go through the CLI or its local HTTP API.

Principles

crew is the only writer of shared state. Agents, Wrangler, your copilot, and outside tools all go through crew to claim, post, emit, and update. This prevents overlapping writes.
Trust by default, verify the output. Agents act without asking. Their work lands in isolated work trees and is approved by a verifier agent, and by you when escalated.
Long work runs as scripts, not sessions. Agents start jobs and sleep until an event wakes them.
Tool-agnostic. Each agent names its own runner (Claude Code, opencode, others) and model.

Where this stands

This is a public beta getting real-world use right now. The core loop -- install, enable, spawn an agent, create a task, watch it work -- is solid. It isn't yet submitted to Obsidian's official community plugin directory; until then, install it with the script above.
