# Writing tasks

- One task, one outcome, one capability. Split anything that needs two different agents.
- Every task needs at least one acceptance criterion before it leaves Inbox.
- Write criteria the verifier can check. Prefer numbers, paths and formats: "under 2,000 triangles", "exported as .glb to ${ASSETS}/props/".
- Add a `--check` command for every criterion a script can verify. Criteria without a check need human or verifier judgment.
- Set `--type` (asset, docs, code) so the right approval tier applies.
- Tag protected work (`--tags canon-lore`) so it always reaches the human.
